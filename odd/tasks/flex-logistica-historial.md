# Flex label logistics change history

Objective: keep every change of etiquetas_envio.logistica_id (old, new, who, when, source). Branch feat/flex-logistica-historial, off origin/main d5cefea9.
Delivery: PR1 = migration (table + trigger, high risk, alone); PR2 = write paths record who and source. Runner: pytest (changed tests only, `@pytest.mark.postgres` for the trigger) + ruff format/check; full suite in CI.

## Specs
- S1 (L1, confirmed 2026-10-27) Every logistica_id change is kept: old value, new value, who (usuario and/or operador), when, source (asignar / masivo / pistoleado / manual). A DB trigger records it, so a future write path cannot skip it. Unchanged values (old IS NOT DISTINCT FROM new) record nothing.
- S2 Who and source come from the write path in the same transaction (transaction-local settings read by the trigger). A path that does not set them still gets a row, with who/source empty.
- S3 Constraints: migration in its own commit/PR; tests in RED first; PRs <= ~400 lines; repo is public (no internal IPs/ports/phones); no AI attribution.
- S4 (L2, started 2026-10-27, L9) Show the history on the label and allow undoing a reassignment. Orchestrator: "go on with Flex L2 (history on the label + undo a reassignment) ... Design it in Stitch first as you said (Precision Operations design system), then implement. No migration expected; if you need one, ask me for the parent."
- S5 (assumption, design decision) Entry point: a history icon button in the row's Acciones cell of TabEnviosFlex opens a modal "Historial de logística" (newest first: fecha, anterior → nueva, origen, usuario/operador; empty state). Visible to anyone with envios_flex.ver.
- S6 (assumption) Undo = put back the logistica_anterior_id of the label's latest history row, only when the current logistica_id still equals that row's logistica_nueva_id (else 409); requires envios_flex.asignar_logistica; the target logística must be active or NULL; it records origen "deshacer" through marcar_origen_logistica. Confirmation step before applying.
- S7 Novedad in the same PR (new area "Envíos Flex"); no migration.
