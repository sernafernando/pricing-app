# Sub-PMs screen redesign

Objective: make granting sub-PMs to a user trivial, following the Open Design prototype (project 72dc0768, `index.html`).
Branches: `feat/sub-pms-scope-grants` (T1, PR #1759) → `feat/sub-pms-por-usuario` (T2a-c, one PR each) → `feat/sub-pms-por-marca` (T3), each PR to main. Strategy: serial PRs, about 400 added lines each. Runner: pytest (backend/.venv), vitest (frontend, pnpm).

## Specs

- S1. "necesito mejorar la vista de sub pms, es imposible darle un sub pm a un usuario" — redesign `MisSubPMs.jsx` after the approved prototype ("eso es lo que buscaba").
- S2. "Por usuario" tab: searchable user list on the left with grant count per user; right panel for the picked user with summary ("Gestiona N pares en M marcas"), pairs grouped BY MARCA with a whole-brand checkbox (indeterminate when partial), search over marcas and categorías, "Mostrar solo lo asignado" toggle, titular and other sub-PMs shown per pair, pending changes highlighted (add / remove).
- S3. "dale, implementalo con los chips agrupados por marca" — the summary chips of what the user already has are grouped by marca (e.g. "LENOVO · 12"), not one chip per pair; removing a chip removes that marca's pairs for the user (pending, not saved).
- S4. Sticky bottom action bar always visible: "+X agregar / −Y quitar", "Descartar", "Guardar", inline confirmation naming the user.
- S5. "Por marca / par" tab: pick a marca, see its categorías with titular and sub-PMs, add one user to several categorías at once, remove a sub-PM from a pair.
- S6. Benchmark from the brief: "darle a Juan toda LENOVO y los Monitores de SAMSUNG" in under 5 clicks.
- S7. Keep existing guarantees of the current container: scoped pair source (admin vs titular, 403 fallback), self-grant exclusion, dirty-guard on user switch, stale-response guard, fail-closed bulk PUT error with `pares_rechazados`, omitted-pairs message.
- S8. (assumption, needed by S2/S5) a scoped read of every sub-PM grant in the caller's writable scope, one query, so per-pair sub-PMs render without N+1.
- S9. Novedades entry in the same PR as the visible change.
